# 0002. 필수 관점 우선 전문가 생성

- 상태: `accepted`

## 맥락

세부 전문가 수를 고정하면 과업마다 필요한 전문성이 달라지는 현실을 반영하지 못한다. 반대로 비용을 줄이기 위해 전문가부터 적게 만들면 일반 프로그램의 기본 보안, 보안 프로그램의 일반 컴퓨터공학, 연구 프로그램의 자료 무결성 같은 필수 관점이 빠질 수 있다.

## 결정

전문가 수를 정하기 전에 필수 관점을 모두 생성한다.

기본 관점에는 사용자 목적, 일반 컴퓨터공학, 정확성, 품질 보증, 기본 보안, 자료 무결성, 사용성, 접근성, 성능, 운영, 복구, 유지보수, 의존성, 문서, 도메인, 연구 방법, 통계, 평가지표, 외부 효과를 포함한다.

각 관점에 참여 프로필을 정한다. P0~P5는 사람의 서열이나 하나의 연속된 등급이 아니다. P0~P3은 기본 참여 심도를 나타내고, P4와 P5는 그 심도에 덧붙이는 요건이다.

- P0 자동 강제: 결정론적 정책이나 자동 검사로 처리한다. 담당 책임 축은 규칙과 실패 처리를 책임한다.
- P1 배정된 전문가가 담당: 요구·프로그래밍·품질 보증에 이미 배정된 전문가가 통상 책임 범위에서 산출물이나 판단을 맡는다.
- P2 지정 시점 자문: 정해진 질문·입력·산출물·기한에 한해 분야 전문가가 참여한다.
- P3 작업 단계 전반 참여: 분야 전문가가 해당 작업 단계의 계획, 중간 판단, 산출물 작성·검토, 인계에 계속 참여한다.
- P4 독립 판정 필요: 구현과 분리된 권한·작업 공간·판정 기준을 가진 검토자를 P0~P3의 기본 심도에 추가한다.
- P5 제한된 조사·연구개발 필요: 내부 지식과 근거가 부족할 때 질문·자원 한도·중단 조건·판단용 산출물을 정한 조사나 실험을 P0~P3의 기본 심도에 추가한다. P5 자체에는 승인 권한이 없으며, 독립 판정이 필요하면 P4도 함께 지정한다.

계획 자료에는 `delivery_depth: P0|P1|P2|P3`, `independent_assessment_required`, `bounded_investigation_required`를 따로 기록한다. `P3+P4`, `P2+P5+P4` 같은 표기는 이 구조를 읽기 쉽게 줄여 쓴 것이다.

그다음 공통 지식·단계·책임 축·이해관계를 기준으로 관점을 묶어 필요한 세부 전문가를 만든다. 구현과 최종 판정처럼 이해관계가 충돌하면 공통 지식이 많아도 분리한다.

모든 세부 전문가는 다음 세 층의 지식을 함께 가진다.

1. 글쓰기·조사·연구·논증·인계 같은 일반 방법 지식
2. 일반 컴퓨터공학 기반과 과업별 심화를 포함한 전문 영역 지식
3. 요구·구현·품질 보증 등 맡은 책임의 판단 지식

## 결과

### 장점

- 전문가 수를 고정하지 않으면서 필수 관점 누락을 방지한다.
- 특화 지식이 일반 역량을 대체하지 않는다.
- 낮은 위험 과업에는 자동 검사와 기본 관점으로 비용을 줄일 수 있다.
- 높은 위험·불확실성·독립성 요구에는 심화 전문가를 늘릴 수 있다.

### 비용

- 관점 목록과 참여 프로필을 먼저 계산해야 한다.
- 관점 중복 제거와 전문가 묶음의 근거가 필요하다.
- P0 검사를 별도 LLM 작업으로 만들지 않고, 서로 맞는 P1 관점을 한 전문가에게 묶는 비용 정책이 필요하다.

## 기각한 대안

### 품질 항목마다 세 책임 전문가를 한 명씩 생성

역할 수와 토큰 비용이 불필요하게 커지고 조정 복잡도가 증가해 기각했다.

### 세 축마다 고정 전문가 한 명만 사용

심화 분야와 독립성 요구를 놓칠 수 있어 기각했다.

### 특화 프로그램에서는 일반 전문가 제거

보안 프로그램도 일반 설계·구현이 필요하고 일반 프로그램도 기본 보안이 필요하므로 기각했다.

## 확인 방법

- 기본 관점이 누락되면 계획 확정을 거부한다.
- 적용하지 않는 관점도 `not-applicable` 근거가 없으면 거부한다.
- 모든 적용 관점에 P0~P3 기본 심도와 P4·P5 적용 여부 및 근거가 있어야 한다.
- 모든 전문가 프로필에 세 층 지식이 있어야 한다.
- 필수 관점이 담당자·산출물·검증 방법 없이 남으면 거부한다.
