# 0004. 근거 기반 완료와 중단 복구

- 상태: `accepted`

## 맥락

LLM이 실제 작업을 하지 않고 `완료`, `pass`, `검증함`이라고 보고할 수 있다. 단일 실행이 시간 초과나 오류로 중단되면 이미 성공한 작업까지 다시 수행할 수 있다. 반대로 자동 재시도 자체를 모두 실패로 보면 일시적 장애를 견디는 워크플로를 만들 수 없다.

## 결정

LLM 응답은 상태 변경 권한을 갖지 않는다. 정책 엔진만 다음 근거를 확인해 작업·단계·미션 상태를 바꾼다.

- 미션·revision·작업·역할·후보본에 결속된 일회성 권한 증표
- 하네스가 직접 수집한 실행·도구 영수증
- 실제 필수 산출물과 SHA-256
- 단계별 필수 입·출력
- 자동 인계 검사와 수신 전문가 확인
- 품질 항목별 독립 판정
- 미해결 차단 사항과 보상 대기 작업의 부재

완료 전에는 일시적 오류에 대한 한도 있는 자동 재시도와 마지막 유효 체크포인트에서의 재개를 허용한다. 이미 검증된 하위 작업은 다시 수행하지 않는다.

완료 뒤 같은 입력·요구 기준선·후보본을 독립적으로 재확인했을 때 수정이나 재실행이 필요하면 기존 완료 판정을 무효화한다. 기존 사건을 삭제하지 않고 원인과 새 시도를 후속 사건으로 남긴다.

외부 효과의 성공 여부가 불명확하면 상태를 대조하기 전 같은 동작을 다시 실행하지 않는다. 중복 제거 키와 외부 식별자를 사용한다.

## 결과

### 장점

- 문자열만으로 완료 상태를 만들 수 없다.
- 일시적 장애와 잘못된 결과를 구분한다.
- 중단 뒤 성공한 작업을 반복하지 않고 실패 지점부터 재개할 수 있다.
- 잘못된 완료 판정도 사건 계보에서 숨기지 않는다.

### 비용

- 작업 시도·오류 분류·체크포인트·재시도 한도 자료형이 필요하다.
- 실행기에서 실제 명령·환경·출력·산출물 영수증을 수집해야 한다.
- 외부 효과마다 중복 제거와 상태 대조 방법이 필요하다.

## 기각한 대안

### LLM의 `gate=pass`를 완료로 사용

무실행·허위 보고를 차단할 수 없어 기각했다.

### 자동 재시도를 모두 완료 기준 위반으로 처리

일시적 장애를 견디지 못하므로 기각했다.

### 전체 미션을 처음부터 재실행

성공한 작업 반복, 비용 증가, 중복 외부 효과 위험 때문에 기각했다.

### 완료 사건을 덮어써서 수정

잘못된 판정의 원인과 계보가 사라지므로 기각했다.

## 확인 방법

- 실제 실행 없이 `pass` JSON만 제출하면 진행이 거부된다.
- 권한 증표를 다른 역할·작업·미션·revision에서 사용하면 거부된다.
- 체크포인트 뒤 중단 시 이미 검증된 하위 작업은 다시 실행되지 않는다.
- 외부 효과 성공 여부가 불명확한 상태에서 맹목 재시도가 거부된다.
- 완료 후 독립 재확인에서 재작업이 필요하면 기존 완료 판정이 무효화된다.
